实测笔记 · WorkBuddy × Grok · 2026.10.30

WorkBuddy 怎么接 Grok 最新模型：自定义 OpenAI 兼容接口实测（grok-4.7）

内置积分不够用了？想直接上 Grok 最新能力，又不想等客户端把模型列表刷出来？

只要手里有一把 OpenAI 兼容 网关的 Key，WorkBuddy 就能把「自定义供应商」接到 Grok。这篇按我自己实机「编辑模型」弹窗走一遍，模型名用的是 grok-4.7。

实测笔记。WorkBuddy 是腾讯云 CodeBuddy 团队的桌面 AI Agent，官方支持 OpenAI 兼容自定义模型。配置字段以本次截图为准；Key 已脱敏，文中不会出现真实密钥。官方说明可对照：WorkBuddy 模型配置 与 腾讯云文档。

01｜先说结论：三步就能挂上

整体就三件事——打开设置、填自定义接口、勾能力并测连：

图 1：流程示意（自制），不是客户端假截图。

入口有两种，效果一样：

1. 头像 → 设置 → 模型 → 添加模型

2. 对话里打开模型选择器，滚到底点 「配置自定义模型」

供应商不在预设列表时，选 自定义。自定义场景下，能力开关不会自动探测——想让 Agent 真正动手改文件、调工具，必须自己勾上 「工具调用」。这点官方也写得很清楚：选标准供应商时能力标记会自动写入；走自定义就要手勾。

02｜准备两样东西

1. WorkBuddy 客户端（已登录即可）

2. 一把 OpenAI 兼容网关的 API Key

我这次用的是 momoai.asia 这类网关：接口地址形如 https://momoai.asia/v1/chat/completions，模型名填控制台里的 id（本文是 grok-4.7）。你换成自己拿到的 Key 就行，别把 Key 发到群里或提交进公开仓库。

Key 只存在本机。官方说法是保存在 workbuddy/models.json；老版本 / CodeBuddy 系路径里也可能看到 ~/.codebuddy/models.json。界面升级后，旧文件里的模型一般仍能在 UI 里编辑，不必手改 JSON。

04｜保存后怎么确认真的接上了

1. 回到对话界面，打开模型选择器

2. 在 自定义 分组里找到刚存的条目（名称多半就是 grok-4.7 或你起的显示名）

3. 选中后发一条真实任务：例如「读一下当前目录结构再改某个小文件」

如果只能干聊、死活不碰本地文件，优先回头看 「工具调用」 有没有勾上——这是自定义接入里最常见的坑。

接上之后，可以按这张清单快速对一遍：

05｜排错（我踩过 / 见过的）

现象先查什么
测试连接失败接口末尾多/少斜杠；Key 前后空格；网关是否可达
model not found模型名大小写、点号是否写成 grok-4.7（以你网关目录为准）
能聊天但不改文件、不调工具没勾「工具调用」
请求路径怪异标准 /v1/chat/completions 一般保持「自定义协议」关闭；非标准路径才考虑开启
保存后对话里找不到看模型选择器的「自定义」分组，或重新打开一次设置页

06｜小结

WorkBuddy 自定义模型的核心就三行：

1. 供应商选 自定义

2. 接口写完整：https://momoai.asia/v1/chat/completions（或你自己的兼容网关）

3. 模型名 grok-4.7，并勾上 工具调用（以及你需要的图片输入 / 思考相关项）→ 测试连接 → 保存

内置列表更新再慢，也能自己把 Grok 最新档挂进桌面 Agent。

如果后面还要换别的模型，接口和 Key 往往不用动，只改「模型名称」一行。统一 Key 调多模型，可在 https://momoai.asia 申请；需要单独走 Grok 通道时，也可参考 https://chongzhi.chatgpt-plus.top/grok/ 这类实测入口（以页面当时说明为准，本文不涉及套餐细节）。
